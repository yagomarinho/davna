## 1. Goal

This document lists the tests of Feature __NNN__, for the user to approve before any test code. After the approval, each item becomes a test that fails first, and only then comes the code that makes it pass (TDD).

- **Base:** the tests cover Stages 3 to 7 of this feature and cite the rule they come from (BR, AC, UC-__P__, D, DM__P__, AD__P__, UI-__P__).
- **Paths:** the test files live next to the code, in `src/**/__tests__/*.spec.ts` of each package (this repository's convention). The paths of new files are proposals that follow Stage 7; if the code asks for another place, the test goes with it.
- **Existing tests:** a card that changes code with tests starts with "Refactoring the existing tests". The old test is adjusted to the new behavior before the code, and fails until the code changes.
- **During the coding:** a ticked item is a test written and passing. A new test that the implementation reveals goes in here before the code; an item that stops making sense is struck through with the reason, never deleted.
- **Items that depend on an open point** carry its number, as in "(point 3)". If the user refuses the recommendation, the item is struck through or rewritten together with the answer.

# 2. The pattern in use

<!-- The repository's test pattern (config/jest, the existing __tests__ and the fakes of each package) and what this feature adds to it. -->

Jest 30 with ts-jest and the `@davna/jest` configuration (`config/jest`), `src/**/__tests__/*.spec.ts` next to the code, fakes in `__fakes__/` or `fakes/` (helpers without `.spec`), `it` in English citing the rule. Unit tests take their effects as fakes (`InMemoryRepository`, `FakeAI`, fake providers), and nothing calls the network, the database or third parties. A test that needs the local Mongo or the `.env` is an integration test, says so in its card, and is listed in section N.

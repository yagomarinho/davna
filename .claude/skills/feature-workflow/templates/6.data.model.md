## 10.2 Rules

- An applied migration is never edited: a correction is a new migration.
- Additive changes whenever possible (a new optional field, a new collection, a new index), so the code in production keeps working during the deploy.
- A new or tighter `$jsonSchema` validator on a collection with data goes in with `validationLevel: "moderate"` and `validationAction: "warn"`, is checked against the existing documents (`db.<collection>.countDocuments({ $nor: [ { $jsonSchema: <schema> } ] })` returns `0`), and only then, in a later migration of the "After" group, becomes `"strict"` / `"error"`.
- A new entity version (`_v: 'v2'`) says how the `v1` documents are read: upgraded on read by the repository, or rewritten by a backfill.
- A backfill is idempotent, runs in batches, first counts what it will change (`countDocuments` with its filter, compared with the expected number), and comes after a `mongodump` of the affected collections.
- An index on a large collection is built before the code that relies on it ships.
